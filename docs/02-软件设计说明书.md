## 1 引言

说明 V1.0 的体系结构、模块职责、数据、接口与关键算法，使实现与需求可对照。产品对外名称「溯知 · SuZhi」，运行主路径为自研异步内核，不以 Stanford STORM 同步引擎为交付实现。

## 2 体系结构

采用 **「浏览器控制台 + FastAPI 服务 + 异步研究管线」** 三层结构。浏览器只负责交互与渲染；服务端负责任务调度、SSE 推送与配置；`AsyncSTORMPipeline` 独占 LLM 与检索 I/O。

```
┌────────────── 浏览器 ──────────────┐
│  溯知控制台 frontend/web           │
│  主题表单 · 演进轴 · SSE 日志      │
│  Markdown/Mermaid · 导出按钮       │
└─────────┬───────────┬──────────────┘
          │ REST      │ SSE
┌─────────┴───────────┴──────────────┐
│  FastAPI  server/app.py            │
│  任务队列 · 并发上限 · ConfigHub   │
└─────────┬───────────┬──────────────┘
          │           │
   AsyncSTORMPipeline    WorkflowStateManager (SQLite WAL)
          │
   AsyncLLM · Retriever · FactGraph · Reviewer · Exporter
          │
   外部：LLM API · SearXNG · 可选本地语料 · Typst
```

**关键决策（摘要）**

| 决策 | 选择 | 理由 |
| :--- | :--- | :--- |
| 运行时 | httpx + asyncio + Pydantic v2 | 去掉 PyTorch/DSPy，内存与启动时间可接受 |
| 交互 | FastAPI + SSE，而非 WebSocket | 单向进度流足够，实现简单、易重连 |
| 状态 | SQLite WAL 检查点 | 单机可恢复，无需额外中间件 |
| 检索 | SearXNG 三轨 + 可选 BM25 + RRF | 适应中文学术与内网语料 |
| 品牌 | 鹿溪四色 Tokens + 双层标识 | 与实验室产品家族一致 |
| 上游 | 保留 Stanford 目录但不接入主路径 | 许可清晰，避免把他人代码登记为原创 |

## 4 进程与运行时

1. `python3 -m server.app` 启动 Uvicorn，托管 `/` 与 `/static`。  
2. `POST /api/v1/research/start` 创建 `asyncio.Task`，事件写入每任务 Queue。  
3. 浏览器 `EventSource` 订阅 `/api/v1/research/stream/{task_id}`。  
4. 阶段完成即 `save_checkpoint`；进程崩溃后可用同一 `task_id` 恢复。  
5. 任务 `finally` 中关闭 LLM / 检索连接池。  
6. CLI 不经过 HTTP，直接构造 Pipeline 并写 `results_async/`。

并发上限 `MAX_CONCURRENT_RESEARCH = 3`，超出返回 HTTP 429。

## 5 数据设计

### 5.1 运行时对象

```
TaskCheckpoint {
  task_id, topic, stage
  personas: [Persona]
  fact_pool: FactPool
  dialogues, outline, article_draft
}

FactEntry { fact_id, claim, source_url, source_title, confidence, perspective, source_quality }
Outline { title, sections: [OutlineSection] }
ArticleDraft { title, content, citations }
```

阶段枚举（检查点）：`INIT → DISCOVERY → CURATION → OUTLINE → WRITING → COMPLETED`。  
SSE 使用更细的事件名（如 `DISCOVERY_START`、`SEARCH_HITS`、`REFLEXION_ACTIVE`）。

### 5.2 持久化

- 检查点：SQLite（WAL），由 `WorkflowStateManager` 维护。  
- 成果目录：`results_async/<task_id>/`，含 `article.md`、`outline.md`、`citations.json`、`fact_pool.json`、`paper.typ`、`slides.marp.md`、`report_standalone.html` 等。  
- 用户配置：`~/.storm/config.toml`（或 ConfigHub 约定路径），密钥仅存本机。

### 5.3 配置层次

优先级从高到低：命令行参数 > 环境变量 > 用户 TOML > 预置 Provider 矩阵。Web「保存并应用」写入用户配置并热替换 `ConfigHub` 内存对象。

## 6 关键算法

### 6.1 视角发现

LLM 按主题生成 N 条「名称: 描述」。中文主题强制中文回复。解析失败时回退内置三类专家（技术 / 产业 / 监管）。

### 6.2 动态探索树

每个节点：视角 × 查询 → 检索 → 抽事实 → 计算相对已有事实的信息增益。增益低于阈值则剪枝，否则派生子问题，深度不超过 `max_depth`。

### 6.3 混合检索与 RRF

对同一查询，Web 列表与本地 BM25 列表按 Reciprocal Rank Fusion 合并：

\[
\mathrm{RRF}(d)=\sum_{r\in R}\frac{1}{k+\mathrm{rank}_r(d)}
\]

默认 \(k=60\)。命中后可走正文提纯；域名落在垃圾站表则丢弃。

### 6.4 事实去重

`FactPool.add_fact` 对 claim 去空白、小写、去尾标点后做 O(1) 哈希集合判断，重复则返回已有条目。

### 6.5 冲突裁决

从事实池抽三元组；同一主谓下客体冲突则生成 `DiscrepancyItem`，写作阶段可嵌入对照表。

### 6.6 评审与反思

评审器按严谨度、真实性、深度等维度打分。总分未达通过线时，仅对问题章节做局部修补，避免整篇重写导致截断。

### 6.7 出版

`MultiFormatExporter` 将 Markdown 正文与引用转为：

- Typst：双栏学术模板；  
- Marp：分页幻灯片；  
- HTML：内联样式的离线研报。

## 7 接口设计

请求体 `ResearchStartRequest`：`topic`、`resume_task_id`、`deep_research`、`max_depth`、`turns`、`perspectives`、`local_docs_dir`。

SSE 事件：`{ task_id, stage, data, tokens_used, progress_pct }`。

配置探测：对 LLM 发最小 chat 或 models 列表；对 SearXNG 发探测查询，返回 RTT 与可用性。

## 8 界面设计

1. **顶栏**：溯知方标、中英字锁、标语、任务/新建/配置/关于、就绪指示。  
2. **左栏**：主题与参数、五段演进轴（不再放终端日志）。  
3. **中栏（研讨现场）**：紧贴正文左侧。流程报幕由 **主持人** 说出；视角入座与下钻由 **嘉宾** 说出；大纲与章节由 **书记员** 说出；红蓝对抗由 **审稿人** 说出。DOM 仅用 `textContent` 写入。  
4. **右栏**：正文 / 参考文献 / 源码；导出组。  
5. **页脚**：实验室主标与出品声明。  
5. **色板**：背景深绿系（`#071510` / `#0C1F18`），强调进化蓝 `#00D2FF`、鹿溪绿 `#0D5E42`、标题金 `#F1C40F`。  
6. **窄屏**：主布局单列堆叠。

方标四层语义：绿底圆角砖、三信源汇流成章、清溪自下而上、源启星与金落点。

## 9 安全设计

1. Provider 查询接口对 api_key 脱敏。  
2. 思考日志使用 `textContent` 写入。  
3. 下载接口限制在任务输出目录内解析文件名。  
4. V1.0 **不提供**用户认证；部署方须放在可信网络。默认监听地址为 `0.0.0.0:8000`，内网暴露前应自行收紧（见 `05`）。  
5. CORS 目前允许任意 Origin，内网加固时应改为白名单。

## 10 测试设计

`tests/` 覆盖异步内核、配置探测、深度研究、服务与 Typst、并发与模糊、端到端管线。登记版本以自研目录测试为准，不把上游 `storm_wiki` 测试计为溯知验收。
