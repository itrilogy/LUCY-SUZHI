# STORM 标题重复与正文结尾截断问题深度根因分析与重构设计

## 1. 现场物理证据与缺陷定位

通过对最新生成任务 `storm_c46f970b` 的产物 `article.md`（字数约 9,000 字）进行逐行逆向溯源，确认了用户反馈的 **2 项核心质量问题** 及其确切物理根因：

### 现象 1：反思润色后产生大量连续重复的 `## 标题`
* **现场实况**：
  ```markdown
  ## 一、产业背景与技术起源
  ## 一、产业背景与技术起源

  ## 二、核心作用机理与工艺架构
  ## 二、核心作用机理与工艺架构

  ## 三、全球市场格局与商业化进展
  ## 三、全球市场格局与商业化进展

  ## 四、合规监管与未来演进趋势
  ## 四、合规监管与未来演进趋势
  ```
* **代码物理根因**：
  1. **初稿起草阶段 (`pipeline.py` L474)**：
     - `_write_single_section` 中大模型自主输出了包含 `## 章节名` 的文本；
     - 外层代码无条件执行了 `return f"## {sec.title}\n\n{content}\n{diagram_md}"`，导致初稿直接带有双重标题。
  2. **反思阶段 (`reviewer.py` L151)**：
     - `apply_reflexion_patch` 将带有双重标题的全文直接塞给模型重写；
     - 大模型保留了双重标题结构，甚至在子段落重写时再度带入标题。

### 现象 2：正文在第四章节结尾严重截断、烂尾直接拼上参考文献
* **现场实况**：
  ```markdown
  **其二，合规即构建的流水线控制。** 与代码工程中在Kotlin DSL或Makefile阶段插入lint与许可证检查类似，知识工程脚手架应在知识构建流程中嵌入合规检查点。例如，当大模型抽取出人物关系或

  ## 参考文献
  [1] [Web Search Result]...
  ```
  （在“例如，当大模型抽取出人物关系或”处戛然而止，后半句及整个总结段落彻底消失！）
* **代码物理根因**：
  - **单次全量输出溢出 `max_tokens` 上限**：
    在 `reviewer.py` 第 159 行中：
    `polished = await self.llm.generate(prompt=prompt, max_tokens=3500)`
    试图在**单次 LLM 调用**中让模型重写整篇 8000~10000 字的长文；
    大模型的 `max_tokens` 设定或 API 单次补全上限（4096 tokens）被耗尽，导致模型生成到最后一章时**中途被硬件掐断**；
    代码将截断的 `polished` 赋值给 `draft.content` 并追加参考文献，最终形成了“烂尾”长文。

## 2. 彻底重构方案与防线设计

```
【原方案缺陷】
整篇 9000 字长文 ──(塞入单次 Prompt)──> LLM 尝试一次性吐出 9000 字 ──> 触发 Token 限制中途掐断 (烂尾截断)
且初稿标题拼接未去重 ──> 叠加为多重标题

【新重构架构】
1. 章节标题净化与防重复守卫 (Title Deduplication Guard)
   - 起草单章节时：正则剥离模型自主生成的开头标题，统一由外层精准挂载唯一 `## 标题`
   - 全局润色时：全局正则抹平所有连续出现的同级重复标题

2. 靶向章节级反思润色 (Section-Targeted Precision Reflexion)
   - 废除单次全量重写；
   - 针对评审报告指出的缺陷，逐个章节执行独立反思增强 (每个章节独立享有 2000 tokens 充足配额)
   - 将润色后的章节无缝缝合回大纲结构，彻底消除长文单次输出截断

3. 截断智能探测与自动续写闭环 (Auto-Continuation Safeguard)
   - 校验章节末尾字符是否以标点（。！？. ! ?）正常收尾；
   - 若检测到句中未完结字符（如“或”、“的”、“和”），自动触发一次短续写并将尾部自然闭合。
```
